# Claude policy for tears

`tears` is the tool you're working on. It enforces a review policy via `@tear`
headers (0 = deeply reviewed, 3 = unreviewed AI output). The policy below
applies to *every file in this repo* — including the source of `tears`
itself. We dogfood.

## The rule

Every text file in this repo carries a `@tear` header on one of its first 5
lines, using the file's comment syntax:

| File type                                          | Header form          |
|----------------------------------------------------|----------------------|
| `.py`, `Makefile`, `.toml`, `.yml`, `.gitignore`   | `# @tear: 3`         |
| `.md`, `.html`                                     | `<!-- @tear: 3 -->`  |
| `.js`, `.ts`, `.go`                                | `// @tear: 3`        |

When you **create** a file, add `@tear: 3` as the first line (or after a
shebang / encoding declaration if present).

When you **edit** a file, set its `@tear` back to `3`. **Never** lower a header
to a value below `3` — promotion is a human act.

Only `.py` is *mechanically* enforced by `tears` in v1. Marking other file
types is honest dogfooding, not enforcement.

A `PostToolUse` hook will eventually do this automatically; until then, by hand.
The diff is the attestation: if a tier dropped in the PR, the reviewer knows
code was touched and not yet re-reviewed.

## Tier meanings

- `0` — Deeply reviewed. Two reviewers or one + domain owner. Security-critical.
- `1` — Reviewed by a human, line by line.
- `2` — Eyeballed for exfiltration / network / obvious security issues. No
  logic review.
- `3` — Unreviewed. AI-generated or AI-touched. This is what your output is.

## What's excluded

- `tests/scan/fixtures/**` — integration test inputs with deliberate tier
  values; don't normalize them.
- `uv.lock` (and lockfiles generally) — autogenerated, any header gets wiped
  on the next resolve.
- `LICENSE` — verbatim third-party text, not ours to tier.
